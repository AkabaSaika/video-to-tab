# 钢琴谱识别（独立功能）

## Context
在吉他 tab 识别之外，新增一个**独立**功能：识别钢琴演奏视频里显示的五线谱（大谱表），导出 MusicXML。后端和前端都与吉他部分分开，只复用视频下载和任务管理这类基础设施。

### 已确认的决策
- **输入：** 钢琴演奏视频（上传文件，或 bilibili / YouTube 链接）。
- **输出：** MusicXML。
- **识别引擎：** homr 0.7.0（AGPL-3.0，基于视觉 Transformer，用 onnxruntime 推理）。项目随之改为 AGPL-3.0 开源（用户已同意）。
- **页面：** 预览、对照原图、导出。逐音符编辑不在本功能范围内，交给 MuseScore。

### 选型依据（对比实验：`/home/akaba/workspace/vtt-cache/piano-spike/NOTES.md`）
测试集为 4 首公有领域曲目，共 75 个小节。

| 指标 | homr | oemer |
|---|---|---|
| 音高 recall（Verovio 清晰 / 降质 / LilyPond 渲染） | 0.976 / 0.958 / 0.900 | 0.67–0.77，个别页面崩溃 |
| 时值 | 0.98 | 0.77–0.90 |
| 和弦完整识别 | 0.99 | 0.75–0.84 |
| 调号 | 全对 | 错 3 个 |
| 每页耗时 | 4–7 s | 144–209 s |
| 内存 | 约 1 GB | 5.6 GB |

两者都兼容项目现有的 OpenCV 5.0 / numpy 2 / Python 3.12，但 homr 需要两处处理：
- 它的依赖声明要求 `opencv<5`，只是元数据，打包时需要绕过；
- 它依赖的 `rapidocr`（只用于识别标题）会额外装上带界面的 OpenCV，与项目的无界面版冲突，应该去掉或替换成空实现。

另外，homr 的 `--read-staff-positions` 在 OpenCV 5 下会出错，不使用这个选项。

### 真实视频上的发现（YouTube L61t-iQkZno《致爱丽丝》滚动乐谱）
- 现有吉他流程的截图方式不适用：它只框住单行五线谱；谱面连续滚动时会丢掉中间内容。
- homr 在完整的大谱表上识别准确，但遇到被画面边缘截断的谱表会输出乱码小节。

## 设计

### 后端：`backend/app/piano/`
- **`systems.py`：** 在一帧中找出大谱表。
  - 用现有的谱表检测找到所有 5 线谱表，把相邻、间距小于约 8 个线距的两个谱表配对成一组；有共同小节线时更可信。
  - 每组外扩约 4 个线距，给加线、符干和力度记号留出空间。
  - 外扩后超出画面的组丢弃，也就是只保留完整的组。
  - 返回每组的裁剪图和它在帧中的纵坐标。
- **`capture.py`：** 从视频中提取有序、不重复的大谱表列表。
  - 按约 5 fps 采样，逐帧取出完整的大谱表。
  - 去重：新的一组与已有各组比较，看缩放到同一宽度后内容是否相同（容忍光标、高亮和压缩噪声）。相同就合并，保留更清晰的那张（边缘能量最高），否则作为新的一组，记下首次出现的时间。
  - 按首次出现的时间排序。
  - 连续滚动和翻页两种视频都适用。
- **`engine.py`：** 封装 homr。
  - 输入一张大谱表图，输出 MusicXML 字符串。
  - 模型只加载一次，后续复用。模型文件的位置可以配置，打包时一起带上，不在运行时从网上下载。
- **`merge.py`：** 把各组的 MusicXML 按顺序拼成一首曲子。
  - 一个钢琴声部，两行谱表，小节从 1 开始连续编号。
  - 相邻组之间，调号、拍号、谱号没有变化时，不重复写出。
- **任务：**
  - 复用 `JobStore`，数据目录为 `data/piano/`，与吉他任务分开。
  - 状态：`downloading`（下载中）→ `capturing`（截取谱表）→ `recognizing`（识别中，显示进度）→ `ready`（完成）/ `failed`（失败）。
  - 每组保存为 `systems/NNN.png`，识别结果保存为 `systems/NNN.musicxml`。
- **接口**（全部在 `/api/piano/` 下）：
  - `POST /api/piano/jobs`：提交视频文件或链接；
  - `GET /api/piano/jobs`：任务列表；
  - `GET /api/piano/jobs/{id}`：任务详情，包括每组的列表（`{id, image, musicxml, ok}`）；
  - `DELETE /api/piano/jobs/{id}/systems/{sid}`：删除某一组；
  - `POST /api/piano/jobs/{id}/systems/{sid}/recognize`：重新识别某一组；
  - `GET /api/piano/jobs/{id}/musicxml`：合并后的整首曲子；
  - `GET /api/piano/jobs/{id}/files/...`：读取任务目录下的文件。
- 所有提示信息使用中文，与现有项目一致。

### 前端：独立页面 `#/piano`
- 顶部导航在"吉他 Tab"和"钢琴谱"之间切换，两边的状态互不影响。
- **输入：** 上传视频或粘贴链接；显示最近的钢琴任务。
- **进度：** 显示下载、截取谱表、识别三个阶段；识别阶段显示"第 k / n 组"。
- **结果页：** 每组一行，左边是原视频截图，右边是 **Verovio**（npm `verovio`，LGPL，WASM）渲染的识别结果。每一行可以"删除"或"重新识别"；识别失败的组会标出来。页面底部可以"导出 MusicXML"，下载合并后的整首曲子。
- 任务号写入网址 `#/piano?job=<id>`，刷新后能回到原任务。

### 许可证与发布
- 仓库根目录加入 `LICENSE`（AGPL-3.0 全文），README 说明 homr 与 AGPL。
- PyInstaller 打包 homr 及其模型，并去掉 `rapidocr`。
- 发布包预计增大约 200 MB，每个识别进程约占 1 GB 内存。

## 测试
- **截图（合成数据）：** 用 Verovio 把公有领域曲目渲染成一张长谱面，按速度滚动合成一段视频（加上压缩噪声和一个移动光标）。要求每组大谱表恰好截到一次，内容完整，顺序正确。另外合成一段翻页视频做同样检查。
- **截断保护：** 被画面边缘截断的谱表不会被截取。
- **合并：** 两个 MusicXML 片段拼接后，小节编号连续，谱号、调号、拍号不重复。
- **识别（有标准答案）：**
  - 在对比实验的测试谱面上，端到端的音高 recall 不低于 0.95（Verovio 清晰版）；
  - 截图环节对识别结果没有损失，即用合成滚动视频走完整流程，结果与直接识别渲染图一致；
  - 没有 homr 模型时相关测试跳过，CI 先下载模型再运行。
- **前端（Vitest）：** 路由、列表状态、"删除 / 重新识别"的请求。
- **真实视频：** 用《致爱丽丝》滚动乐谱视频走完整流程，人工抽查。

## 不在范围内
逐音符编辑、播放和试听、识别多个乐器组成的总谱、手写谱、指法和踏板等附加记号的校验。
