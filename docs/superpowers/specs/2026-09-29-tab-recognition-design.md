# Tab 符号识别（子项目 1：识别引擎 + 评测工具）

## Context
用户希望把视频里的 tab 谱转成可编辑的 Guitar Pro 文件。整体分两个子项目：
1. **识别引擎 + 评测工具**（本 spec）
2. 识谱界面 + 用 alphaTab 导出 `.gp`（后续单独设计）

制谱软件和写谱习惯各不相同，所以设计上不针对某种软件写死规则。做法是：
- 先检测谱面有哪些元素，再决定用什么策略；
- 字形识别用多字体合成数据训练；
- 每一处识别结果都带置信度，留给子项目 2 的人工修正；
- 用"视频 + 作者公开的 GP 文件"量化准确率。

### 首个评测样本
- **视频：** bilibili `BV1yBcEeXEVn`，1080p，约 165 秒，由 Guitar Pro 导出，分段横向滚动，每次跳一段约 2.7 秒。
- **标准答案：** `data/tabs/[7弦]AveMujica+KiLLKiSS.gp`，取 **Guitar Mutsumi** 声部。`data/` 已被 gitignore，不提交。
- **谱面内容：**
  - 7 弦吉他，Drop A 定弦，GP 中的音高为 33 40 45 50 55 59 64；
  - 只有 TAB，下方有节奏记号，上方有 P.M. 标记和小节号，速度 ♩=200，拍号 4/4；
  - 黄色高亮一次框住整个小节，**不是逐音符移动的光标**。
- **对齐方式：** 视频从第 13 小节开始，第 1–13 小节为空拍。视频里的小节号等于 GP 中的小节序号（从 1 开始）。
- **已核对：**
  - GP 的 0 号弦 = 最低音弦 = 谱面最下面那根线；
  - 第 14 小节为 7/7 双音，节奏"四分–八分–四分–八分–四分"，与画面一致；
  - GP 在 tab 中用**圆圈数字表示二分音符**（第 18 小节）；
  - 第 23 小节末拍为 8 品、½ 推弦加 <13> 泛音。
- **现有流程的输出：** 截图和拼接可以直接用。自动区域检测置信度 1.00，输出 39 行，第 13–26 小节连续、没有重复。

## 已确认的决策
- **时值：** 识别 tab 下方的节奏记号（符干、横梁、单独符尾、附点、连音数字，以及表示二分音符的圆圈），再用"每小节总时值 = 拍号"约束求解纠错。没有节奏记号时，按水平间距估算，并标为低置信度。
- **品格数字：** HOG 特征 + OpenCV 自带的 SVM（`cv2.ml`），用多字体合成数据训练。模型文件随代码提交，不新增依赖。
- **识别对象：** 在现有流程产出的行图上识别（即 `Page` 的图像），不重新处理视频。

## 数据模型（`backend/app/omr/model.py`）
```
Score:   strings:int, tuning:list[int] (MIDI，低→高), tempo:int|None, measures:list[Measure]
Measure: number:int|None（识别到的小节号）, time:(num,den)=(4,4), beats:list[Beat], line:int, x0:int, x1:int
Beat:    duration:int (1/2/4/8/16/32), dots:int, tuplet:int|None (如 3), rest:bool,
         notes:list[Note], x:int, confidence:float
Note:    string:int（0 = 最低音弦）, fret:int, confidence:float
```
- 可以序列化成 JSON，作为子项目 2 前后端之间的统一格式。
- 定弦默认值：6 弦为 E 标准；7 弦为 B 标准（`[35,40,45,50,55,59,64]`）；可以手动覆盖。

## 识别流程（`backend/app/omr/`）
逐行进行：
1. **谱线：** 用 `region.detect_staves`，取线数最多的谱表。线数就是弦数，每根线的纵坐标对应一根弦（最下面的线是 0 号弦）。小节线用 `stitch.find_bars`，切出各个小节。
2. **品格数字：**
   - 在谱表范围内（上下各留半个线距）取墨迹，去掉谱线和小节线；
   - 找连通域，横向间隔很小的相邻连通域合并成多位数；
   - 每个数字归一化到固定尺寸，用 HOG + SVM 分类，得到 0–9 和置信度；
   - 按数字中心纵坐标分配到最近的弦；离所有弦都太远的丢弃；
   - 被圆圈包围的数字（外圈连通域）记为"二分音符"提示。
3. **休止符：** 谱表内不在弦上的独立符号，分为全休止、二分休止（实心块）、四分、八分、十六分休止。由同一分类器识别（额外的类别）。
4. **拍分组：** 同一小节内，横坐标中心相差不超过约 0.6 个数字宽度的音符归为一拍。拍按横坐标排序，每一拍的横坐标取中位数。
5. **节奏记号**（谱表下方区域）：在每一拍的横坐标附近检测：
   - 有无符干（竖直细线）；
   - 符干下端连着几条横梁（连到相邻符干的粗横线），或者几条单独符尾；
   - 附点（符干右下方的小圆点）；
   - 横梁或括号下方的连音数字"3"。

   按 GP 的画法换算成时值候选：
   - 无符干、无圆圈 → 全音符；
   - 圆圈加符干 → 二分音符；
   - 有符干、无横梁无符尾 → 四分音符；
   - 横梁或符尾每多一条，时值再减半。
6. **小节约束求解：** 每一拍保留若干个带概率的时值候选。求一个组合，使总时值正好等于拍号，同时联合概率最大（动态规划）。如果无解，就保留各拍的最优候选，把整个小节标为低置信度。
7. **小节号：** 用同一个数字分类器识别每条小节线右上方的小号数字，得到小节编号。识别失败时，按行内顺序接着前一小节递增编号。

## 评测（`backend/app/omr/gpif.py`、`backend/app/omr/evaluate.py`）
- **读取标准答案：** `gpif.read_track(path, track_name)` 读取 GP7/8 文件（zip 里的 `Content/score.gpif`），返回同样的 `Score` 模型：
  - 每个音符取 String 和 Fret；
  - 时值取 NoteValue、AugmentationDot 和 PrimaryTuplet；
  - 只取第一个声部。
- **命令：** `python -m app.omr.evaluate VIDEO GP --track NAME`。它先跑现有流程和识别，再按小节号对齐标准答案，输出三项准确率：
  - **品格：** 标准答案里的每个音符（弦 + 品格）是否被识别到，即 recall；
  - **拍分组：** 各拍的音符集合是否一致；
  - **时值：** 在拍分组正确的前提下，时值、附点、连音是否一致。

  另外列出出错最多的小节，便于调试。

## 模型训练（`backend/app/omr/train.py`）
- 生成合成数据：
  - 字体：Hershey 字体、`backend/app/omr/fonts/` 中随代码提交的开源字体（DejaVu Sans / Liberation Serif 等，许可证允许再分发），以及系统字体；
  - 字号：8–30 px；
  - 背景：数字画在白框里并压在谱线上；
  - 干扰：加噪声、模糊、JPEG 压缩、轻微平移和缩放；
  - 类别：数字和各种休止符。
- 训练 HOG + SVM，输出 `backend/app/omr/models/glyphs.xml`，随代码提交。
- 训练脚本可以重复运行，结果可复现（固定随机种子）。

## 验收目标（在首个样本上，第 13–148 小节的 Mutsumi 声部）
- 品格准确率 ≥ 95%
- 拍分组准确率 ≥ 90%
- 时值准确率 ≥ 85%

在原型阶段先实测。如果达不到，先调整算法，再写实施计划。

## 不在范围内
- 演奏技巧：P.M.、推弦、泛音、滑音、连音线；
- 多声部、五线谱、歌词；
- 识谱界面和 `.gp` 导出（子项目 2）。
