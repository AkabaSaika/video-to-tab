# 鼓谱识别（独立功能）

## Context
新增与吉他 tab、钢琴谱并列的**独立**功能：识别鼓演奏视频中显示的五线谱式鼓谱（打击乐谱号的 5 线谱），导出 MusicXML 和 MIDI。它有独立的后端模块和前端页面，复用下载、任务管理、截图拼接和节奏求解等已有组件。

### 已确认的决策
- **输入：** 鼓演奏视频（上传文件，或 bilibili / YouTube 链接）。
- **输出：** MusicXML（unpitched 音符加乐器定义）和 MIDI（GM 第 10 通道）。
- **页面：** 与钢琴谱相同，提供预览、对照原图、导出三项功能。逐音符编辑交给 MuseScore，不在本功能内做。
- **乐器对应表：** 默认采用通用约定；页面上可以选预设，也可以逐个位置修改。修改后直接重新生成导出文件，不需要重新识别。
- **识别方法：** 自研经典 CV，不引入新依赖。

### 选型依据（对比实验：`/home/akaba/workspace/vtt-cache/drum-spike/NOTES.md`）
测试集为 8 段鼓谱，共 38 个小节、459 个音符。"乐器 + 时间位置"都正确的比例：

| 渲染版本 | 自研 CV | homr |
|---|---|---|
| 清晰 | 0.94 / 0.95 | 0.40 / 0.67 |
| 降质 | 0.85 / 0.86 | — |
| 1280 px（线距约 10 px） | 0.76 / 0.80 | — |
| LilyPond 渲染 | 0.89 / 0.91 | — |

表中数值为 recall / precision。

- 自研 CV 的声部划分为 1.0，每页耗时约 0.1 s。
- homr 把打击乐谱号当成中音谱号，也不认识 × 形符头，因此不适用。

### 真实视频（YouTube Pxt93gz8jas，Drumscribe《The Middle》）
- 谱面是 Guitar Pro 风格的横向分段滚动条带，位于镜头画面下方，带黄色高亮和光标，谱号只在第一屏出现。
- 整份谱写成**单声部**：底鼓和手共用向上的符干，踩镲踏板用向下的符干，且不写休止符。谱面上还有圆圈 ×、重音和左右手（L/R）标记。
- 截图方面：吉他 tab 的截图拼接流程可以直接用（`--roi 0,840,1920,240`，得到 34 页）；钢琴的截图逻辑不适用。

## 设计

### 后端：`backend/app/drums/`
- **`capture.py`：** 从视频中截出谱表条带或谱表组。
  - **横向条带：** 复用吉他的区域检测、分页和拼接流程（`region` / `segment` / `compose` / `stitch`）。其中区域检测要能找到 5 线谱。
  - **翻页或纵向滚动：** 复用钢琴的截取逻辑，但把每组谱表的谱表数设为 1。
  - **自动选择：** 检测到的谱面区域是单条横向条带时，走横向条带流程；是多个上下堆叠的谱表组时，走翻页 / 纵向滚动流程。
  - 画面中有深色镜头区域时，先裁出谱面区域，再判断明暗。
- **`recognize.py`：** 把一行谱面识别成小节列表。
  - **谱表：** 复用钢琴的谱线查找，加上对比实验里的两个补救手段：Otsu 阈值重试，以及按行明暗查找。
  - **符头：** × 形用模板匹配，实心和空心符头单独检测。记录每个符头的位置（线 / 间序号，加线也算）和形状（×、实心、空心、圈 ×）。
  - **声部：** 按符干方向分声部。Guitar Pro 的单声部写法中，第二声部没有休止符，要按横向坐标与第一声部对齐来确定起点。
  - **节奏：** 复用 `omr.rhythm` 的横梁计数（向上的符干翻转图像后处理）和 `omr.solve` 的小节时值求解，并处理附点休止。
  - **休止符和拍号：** 休止符用 `omr.glyphs` 的分类器（可重新训练）。拍号识别起始处的数字；识别不出时按 4/4，页面上可改。
  - **小节：** 按小节线切分；页面边缘不完整的小节依赖拼接后的重排来补全。
- **`model.py`：** `DrumScore(title, tempo, time, measures)`，其中每个小节包含多个声部，每个声部是一串拍。
  - 每一拍：`onset`、`duration`、`dots`、`tuplet`、`rest`、`notes`。
  - 每个音符：`step`、`octave`、`notehead`、`accent`、`ghost`、`open`。
  - 只保存原始的位置和符头形状，不保存乐器；乐器在导出时按对应表换算。
  - 提供 JSON 往返，并能读取旧格式的数据。
- **`instruments.py`：**
  - 默认对应表，对应到 GM 音色号：吊镲 49 A5×；闭镲 42 G5×；开镲 46 G5× 加 "o"；叮叮镲 51 F5×；高嗵鼓 50 E5；中嗵鼓 47 D5；军鼓 38 C5；落地嗵鼓 43 A4；底鼓 36 F4；踩镲踏板 44 D4×。
  - 预设：Guitar Pro、MuseScore。
  - 支持用户覆盖：一张"(位置, 符头) → 乐器"的表。
- **`export.py`：**
  - **MusicXML：** 使用 `<unpitched>`，加上 `<score-instrument>` / `<midi-instrument>` 和 `<instrument id>`，符头按乐器设置，谱号为 percussion。
  - **MIDI：** 自写 SMF type 1 写出器，GM 第 10 通道，力度考虑重音和鬼音。
- **任务：** 复用 `JobStore`，数据目录为 `data/drums/`。
  - 状态：`downloading`（下载中）→ `capturing`（截取谱面）→ `recognizing`（识别中，显示进度）→ `ready`（完成）/ `failed`（失败）。
  - 每页的原图、识别结果（DrumScore 片段）和渲染用的 MusicXML 分别保存。
- **接口**（全部在 `/api/drums/` 下）：
  - `POST /api/drums/jobs`：提交视频文件或链接；
  - `GET /api/drums/jobs`：任务列表；
  - `GET /api/drums/jobs/{id}`：任务详情；
  - `DELETE /api/drums/jobs/{id}/pages/{pid}`：删除某一页；
  - `POST /api/drums/jobs/{id}/pages/{pid}/recognize`：重新识别某一页；
  - `GET` / `PUT /api/drums/jobs/{id}/mapping`：读取和修改乐器对应表；
  - `PUT /api/drums/jobs/{id}/settings`：修改拍号和速度；
  - `GET /api/drums/jobs/{id}/musicxml`、`GET /api/drums/jobs/{id}/midi`：导出；
  - `GET /api/drums/jobs/{id}/files/...`：读取任务目录下的文件。
- 所有提示信息使用中文。

### 前端：独立页面 `#/drums`
- 顶部导航增加"鼓谱"，与"吉他 Tab""钢琴谱"并列，各页面的状态互不影响。
- 进度页和输入页（包括最近的任务）与钢琴页相同。
- **结果页：**
  - 每页一行，左边是原图，右边是 Verovio 渲染的识别结果，可"删除"或"重新识别"；
  - "乐器对应"面板可以选预设或逐项修改，修改后立即重新渲染；
  - 可修改拍号和速度；
  - 提供"导出 MusicXML"和"导出 MIDI"。
- Verovio 按需加载，复用钢琴页已有的加载逻辑。

## 测试
- **识别准确率（有标准答案）：** 用对比实验的 8 段鼓谱，按实验中的评测方法计算"乐器 + 起点"的 recall 和 precision。清晰渲染不低于 0.90，降质不低于 0.80。
- **截图：**
  - 用合成的 Guitar Pro 风格横向分段滚动视频（带高亮和光标）检验，每个小节恰好出现一次、顺序正确；
  - 合成的翻页视频同样检验。
- **单声部写法：** 踏板声部不写休止符时，靠横向对齐得到正确的起点。
- **导出：**
  - MusicXML 能被 music21 读回（仅开发环境），乐器和起点一致；
  - MIDI 用自写读取器（或 music21）读回，通道、音色号和时间一致；
  - 修改乐器对应表后，导出结果随之改变。
- **测试数据：** 由生成脚本产生并提交到 `backend/tests/data/drums`。根目录 `.gitignore` 只忽略 `/data/`，所以这里能正常提交。
- **真实视频：** 用 Drumscribe 的视频走完整流程，人工抽查。

## 不在范围内
逐音符编辑、播放和试听、装饰音 / 滚奏 / 倚音、包含多个乐器谱表的总谱、手写谱。
